Повторение FastAPI перед проектными занятиями

В этой статье рассматриваются основные темы, которые уже встречались в курсе по созданию сайтов на Python с использованием FastAPI. Материал построен вокруг кода курса: сначала приводится фрагмент программы, затем объясняется, как он работает, после этого дается дополнительный пример и практическое задание.

Цель повторения - связать отдельные темы в единую картину. К концу статьи должно быть понятно, как браузер отправляет запрос, как FastAPI выбирает маршрут, как Python-функция формирует ответ, как HTML-шаблон получает данные, как формы отправляют информацию на сервер, как работают cookies, сессии, регистрация, вход пользователя и база данных SQLite через SQLAlchemy.

Материал можно читать последовательно. Каждая тема является небольшой самостоятельной частью, но все они постепенно складываются в одно веб-приложение.

Как читать примеры

Код в этой статье не нужно воспринимать как набор строк для запоминания. В каждом примере важно видеть цепочку: URL в браузере -> HTTP-запрос -> маршрут FastAPI -> функция Python -> ответ сервера -> результат в браузере.

Если пример содержит HTML-шаблон, нужно отдельно проследить, какие данные передаются из Python в шаблон и в каком месте страницы они выводятся. Если пример содержит форму, нужно определить, каким методом она отправляется, на какой адрес уходит запрос и какие параметры получает сервер.

Большая картина: как работает интернет, браузер и сервер

Прежде чем переходить к FastAPI, полезно определить роли участников. Браузер является клиентом: он показывает страницу пользователю и отправляет запросы. Сервер является программой, которая принимает эти запросы, выполняет нужную логику и возвращает ответ. FastAPI в данном курсе выступает серверной частью сайта.

Запрос и ответ передаются по правилам HTTP. В запросе указывается метод, например GET или POST, путь, например /login, дополнительные заголовки, cookies и иногда тело запроса. В ответе сервер возвращает статус, заголовки и тело ответа: строку, JSON, HTML-страницу или перенаправление.

Представь сайт как разговор. Браузер задает вопрос серверу, а сервер отвечает. В FastAPI ответом управляет Python-код. Поэтому, когда смотришь на любой пример ниже, всегда ищи три части: адрес, функцию и ответ.

Интернет в этом курсе можно понимать как обмен сообщениями между браузером и сервером. Браузер - программа на локальном компьютере. Сервер - программа FastAPI, которая запускается командой uvicorn. Когда пользователь открывает адрес сайта, браузер отправляет HTTP-запрос. Сервер принимает запрос, ищет подходящий маршрут, выполняет Python-функцию и возвращает HTTP-ответ. Именно эту цепочку следует видеть в каждом примере.

Браузер пользователя
    -> отправляет HTTP-запрос: GET /
FastAPI-приложение
    -> ищет маршрут @app.get("/")
    -> вызывает функцию index()
Python-функция
    -> возвращает строку, JSON, HTML-шаблон или RedirectResponse
FastAPI
    -> превращает результат в HTTP-ответ
Браузер
    -> показывает ответ как страницу или данные
  • HTTP - это набор правил, по которым браузер и сервер общаются. Запрос содержит метод, путь, заголовки, cookies и иногда тело запроса.
  • Метод GET обычно используется, чтобы получить страницу или данные. В курсе GET применялся для главной страницы, формы, таблицы, страницы входа, удаления по ссылке и просмотра объекта.
  • Метод POST обычно используется, чтобы отправить данные на сервер. В курсе POST применялся для отправки формы, регистрации, входа, добавления записи в список или базу.
  • Путь или route - это часть адреса после домена. Например, /, /form, /add, /delete, /book/5.
  • Query-параметры идут после знака вопроса: /delete?index=0. Path-параметры находятся прямо внутри пути: /eat/apple или /book/5.
  • Cookie - маленькая строка, которую сервер сохраняет в браузере. При следующих запросах браузер сам отправляет cookie обратно на сервер.
  • Сессия - способ хранить важную информацию на сервере, а в браузере держать только случайный session_id.
  • База данных нужна, чтобы данные не исчезали после перезапуска сервера. До базы данных список kids и словарь users жили только в памяти Python.
GET / открыть главную страницу
GET /form получить HTML-форму
POST /form отправить поля формы на сервер
POST /add добавить новую запись
GET /delete?id=3 удалить запись с id=3
GET /eat/apple path-параметр fruit = "apple"
GET /eat?fruit=apple query-параметр fruit = "apple"

ТЕМА 1. Первый сервер FastAPI и первый маршрут

Любое приложение FastAPI начинается с создания объекта приложения. Затем к нему добавляются маршруты. Маршрут связывает HTTP-метод и адрес с функцией Python.

В первой теме рассматривается базовая схема работы FastAPI: пользователь открывает адрес в браузере, FastAPI находит маршрут, вызывает связанную с ним функцию и возвращает ответ.

Пример кода

from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def index():
    return "Hello World!"

Разбор кода

  • Строка from fastapi import FastAPI импортирует класс FastAPI. Без этого класса нельзя создать веб-приложение.
  • app = FastAPI() создает объект приложения. Именно к этому объекту добавляются маршруты через декораторы @app.get и @app.post.
  • @app.get("/") означает: когда браузер отправит GET-запрос на путь /, нужно вызвать функцию index.
  • def index(): - обычная Python-функция. Отличие только в том, что ее вызываешь не вручную, а FastAPI при приходе HTTP-запроса.
  • return "Hello World!" возвращает тело ответа. Браузер увидит простую строку, а не HTML-страницу.
  • Запуск делается командой uvicorn app:app --reload. Первое app - имя файла app.py, второе app - переменная app = FastAPI().
  • --reload перезапускает сервер после изменения кода. Это удобно: код изменен, сохранил файл, сервер сам перезапустился.

Дополнительный пример

from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
def hello():
    return "Привет! Это мой первый маршрут."

@app.get("/about")
def about():
    return "Этот сайт написан на FastAPI."

Разбор дополнительного примера

  • В примере два маршрута: /hello и /about. Один сервер может иметь много маршрутов.
  • При открытии http://127.0.0.1:8000/hello, FastAPI вызовет hello(). При открытии /about, вызовет about().
  • Имена функций могут быть любыми, но лучше выбирать понятные: hello, about, index.
  • Маршрут и функция связаны декоратором. Если убрать @app.get("/hello"), функция hello останется обычной Python-функцией и браузер не сможет ее вызвать.
  • Этот пример показывает основу всего курса: URL -> декоратор -> функция -> return -> ответ браузеру.

Типичные ошибки

  • Частая ошибка: запустить uvicorn main:app, когда файл называется app.py. Нужно uvicorn app:app --reload.
  • Частая ошибка: забыть скобки FastAPI(). Тогда app не станет приложением.

ТЕМА 2. Path-параметры и query-параметры

Path-параметр является частью самого адреса. Query-параметр является дополнительной настройкой запроса. На практике path-параметры часто применяются для идентификаторов объектов, а query-параметры - для фильтрации, поиска и дополнительных опций.

В этой теме рассматривается передавать данные в адресе: часть данных может быть прямо в пути, а часть - после знака вопроса.

Пример кода

from fastapi import FastAPI

app = FastAPI()

@app.get("/eat/{fruit}")
def eat1(fruit: str):
    return f"Ты съел {fruit}"

@app.get("/eat")
def eat2(fruit: str):
    return f"Ты съел {fruit}!"

Разбор кода

  • В маршруте /eat/{fruit} часть fruit находится внутри адреса. При открытии /eat/apple, переменная fruit получит строку "apple".
  • Фигурные скобки в пути говорят FastAPI: это не обычный текст, а переменная из URL.
  • В маршруте /eat параметр fruit не находится в пути. Его нужно передать как query-параметр: /eat?fruit=apple.
  • Знак вопроса отделяет путь от query-параметров. После него идут пары имя=значение.
  • Аннотация fruit: str говорит FastAPI, что fruit должен быть строкой. Если указать int, FastAPI попробует преобразовать значение в число.
  • Path-параметры хорошо подходят для адресов конкретных объектов: /book/7, /user/15, /post/100.
  • Query-параметры хорошо подходят для настроек запроса: /search?text=cat, /users?page=2, /books?year=2020.

Дополнительный пример

from fastapi import FastAPI

app = FastAPI()

@app.get("/square/{number}")
def square(number: int):
    return number * number

@app.get("/repeat")
def repeat(word: str, count: int = 1):
    return word * count

# /square/5 вернет 25
# /repeat?word=hi&count=3 вернет hihihi

Разбор дополнительного примера

  • number: int показывает, что FastAPI должен получить число из пути. /square/5 сработает, а /square/abc даст ошибку проверки данных.
  • В repeat параметр word обязателен, потому что у него нет значения по умолчанию. count имеет значение по умолчанию 1.
  • При открытии /repeat?word=hi, count будет равен 1. При открытии /repeat?word=hi&count=3, count будет равен 3.
  • Символ & разделяет несколько query-параметров.
  • Этот пример учит выбирать вид параметра: number важен как часть адреса, а count похож на настройку запроса.

Типичные ошибки

  • Если параметр написан в декораторе как {fruit}, то в функции тоже должно быть fruit.
  • Если параметр обязательный query и его не передать, FastAPI вернет ошибку 422.

ТЕМА 3. POST-запрос и Pydantic-модели

POST-запрос используется, когда клиент отправляет данные на сервер. Если данные приходят в формате JSON, FastAPI может автоматически передать их в Pydantic-модель, проверить типы и создать удобный Python-объект.

В этой теме рассматривается, как сервер принимает JSON-данные и проверяет их через Pydantic-модель.

Пример кода

model.py

from pydantic import BaseModel

class Pet(BaseModel):
    name: str
    age: int
    animal: str

class User(BaseModel):
    name: str
    age: int
    gender: bool
    is_teacher: bool
    has_dog: bool
    pets: list[Pet]

app.py


@app.post("/new_user")
def new_user(user: User):
    return f"Тебя зовут {user.name}, тебе {user.age} лет и у ученика {len(user.pets)} домашних питомцев"

Разбор кода

  • GET обычно получает данные, а POST отправляет данные. Поэтому новый пользователь создается через @app.post.
  • BaseModel - класс из Pydantic. Он нужен, чтобы описать форму JSON-данных.
  • Pet описывает одного питомца: name, age, animal. Все поля обязательны, потому что нет значений по умолчанию.
  • User описывает пользователя. Поле pets: list[Pet] означает список объектов Pet.
  • Когда клиент отправляет JSON на /new_user, FastAPI сначала проверяет структуру JSON по модели User.
  • Если в age отправить строку вместо числа, FastAPI попробует преобразовать ее. Если не получится, вернет ошибку валидации.
  • После проверки внутри функции user уже не словарь, а объект User. Поэтому можно писать user.name, user.age, user.pets.
  • len(user.pets) считает количество питомцев. Это обычный Python-код, который работает после получения данных от HTTP-клиента.

Дополнительный пример

model.py

from pydantic import BaseModel

class Product(BaseModel):
    title: str
    price: int
    tags: list[str]

app.py


@app.post("/product")
def create_product(product: Product):
    return {
        "message": "Товар получен",
        "title": product.title,
        "price_with_delivery": product.price + 300,
        "tags_count": len(product.tags)
    }

# JSON для проверки:
# {
#   "title": "Клавиатура",
#   "price": 2500,
#   "tags": ["computer", "keyboard"]
# }

Разбор дополнительного примера

  • Product - модель для тела POST-запроса. Она говорит серверу, какие поля ждать в JSON.
  • Функция create_product принимает product: Product. FastAPI сам создает этот объект из тела запроса.
  • Внутри return возвращается словарь. FastAPI превратит словарь в JSON-ответ.
  • price_with_delivery показывает, что сервер не обязан просто повторять присланные данные. Он может выполнять вычисления.
  • tags_count показывает работу со списком. Если tags содержит два элемента, len(product.tags) вернет 2.
  • Такой подход удобен для API, где браузер или другая программа отправляет JSON, а сервер возвращает JSON.

Типичные ошибки

  • Если забыть наследование BaseModel, FastAPI не поймет модель как схему данных.
  • Если поле называется title, в JSON тоже должно быть title, а не name.

ТЕМА 4. Возврат объекта Pydantic как JSON-ответа

В этой теме видишь, что сервер может возвращать не только строки, но и структурированные данные в формате JSON.

Пример кода

from fastapi import FastAPI
    from pydantic import BaseModel
    
    app = FastAPI()
    
    
    class Pupil(BaseModel):
        first_name: str
        surname: str
        grade: int
        class_letter: str
        is_excellent: bool
        hobbies: list[str]
    
    @app.get("/{grade}")
    def pupil(grade: int, class_letter: str):
        return Pupil(
            first_name="Вася",
            surname="Пупкин",
            grade=grade,
            class_letter=class_letter,
            is_excellent=True,
            hobbies=["хоккей", "шахматы"]
        )

Разбор кода

  • Модель Pupil описывает структуру ученика: имя, фамилия, класс, буква класса, отличник или нет, хобби.
  • Маршрут @app.get("/{grade}") получает grade из пути. Например, /7 передаст grade = 7.
  • Параметр class_letter: str не указан в пути, значит FastAPI ждет его как query-параметр: /7?class_letter=A.
  • Функция возвращает Pupil(...), а не строку. FastAPI автоматически превращает Pydantic-объект в JSON.
  • Это важно: сервер может возвращать структурированные данные, которые удобно читать JavaScript-программе, другому серверу или документации /docs.
  • Поле hobbies: list[str] превращается в JSON-массив строк. Python-список становится JSON-списком.
  • is_excellent=True превращается в JSON true. В Python пишется True, в JSON отображается true.

Дополнительный пример

from pydantic import BaseModel
    
    class BookInfo(BaseModel):
        title: str
        author: str
        year: int
        available: bool
        genres: list[str]
    
    @app.get("/book/{year}")
    def book(year: int, title: str):
        return BookInfo(
            title=title,
            author="Неизвестный автор",
            year=year,
            available=True,
            genres=["учебная", "python"]
        )
    
    # /book/2026?title=FastAPI

Разбор дополнительного примера

  • BookInfo работает так же, как Pupil. Это схема ответа.
  • year берется из path-параметра, потому что находится в /book/{year}.
  • title берется из query-параметра, потому что в маршруте нет {title}.
  • Сервер собирает объект BookInfo и возвращает его. Клиент получает JSON с одинаковыми полями каждый раз.
  • Если позже приложение будет показывать книги в HTML, подобная структура поможет понять, какие поля есть у книги: title, author, year.

Типичные ошибки

  • Не путать модель входных данных и модель ответа. В курсе Pydantic использовался и для приема JSON, и для формирования ответа.

ТЕМА 5. HTML: что браузер получает от сервера

HTML является языком разметки страницы. Сервер может вернуть HTML как обычный текст, но браузер отобразит его как страницу: заголовки, абзацы, ссылки, формы и таблицы.

В этой теме связываются backend и frontend: сервер возвращает HTML, а браузер превращает его в страницу.

Пример кода

<!doctype html>
    <html>
    <head>
        <meta charset="UTF-8">
        <title>Название сайта</title>
    </head>
    <body>
          <h1>Самый простой HTML файл!</h1>
    </body>
    </html>
    
    <!DOCTYPE html>
    <html lang="en">
    <head>
        <meta charset="UTF-8">
        <title>Страница</title>
    </head>
    <body>
        <h1>Эта страница принадлежит Васе Пупкину</h1>
        <p>У него 3 кота</p>
        Вот их имена:
        <ul>
            <li>Барсик</li>
            <li>Кузя</li>
            <li>Мурзик</li>
        </ul>
        <p>Вася хочет ещё одного кота</p>
    </body>
    </html>

Разбор кода

  • HTML - это текстовая разметка страницы. Браузер читает теги и показывает пользователю страницу.
  • <!doctype html> сообщает браузеру, что документ написан на HTML.
  • <html> содержит всю страницу, <head> содержит служебную информацию, <body> содержит видимую часть.
  • <meta charset="UTF-8"> нужно, чтобы русские буквы отображались правильно.
  • <title> показывает заголовок вкладки браузера.
  • <h1> - главный заголовок страницы, <p> - абзац, <ul> - список, <li> - элемент списка.
  • В коде 7/html/index.html страница пока статическая: имена котов написаны прямо в HTML. Python не меняет их.
  • Сервер FastAPI в этой теме не рисует страницу. Он только отправляет HTML-файл браузеру. Рисует страницу уже браузер.

Дополнительный пример

<!doctype html>
    <html>
    <head>
        <meta charset="UTF-8">
        <title>Профиль</title>
    </head>
    <body>
        <h1>Профиль ученика</h1>
        <p>Имя: Иван</p>
        <p>Возраст: 14</p>
        <ul>
            <li>Python</li>
            <li>FastAPI</li>
            <li>HTML</li>
        </ul>
    </body>
    </html>

Разбор дополнительного примера

  • Этот пример можно сохранить как profile.html. Он не зависит от Python и откроется даже как обычный файл.
  • Страница самодостаточная: все данные написаны прямо внутри HTML.
  • Минус статической страницы в том, что для другого ученика нужно вручную менять HTML.
  • Именно поэтому дальше используется Jinja2: Python сможет передавать данные в HTML, а шаблон будет подставлять значения.
  • HTML отвечает за структуру того, что видит пользователь. FastAPI отвечает за получение запроса и выбор ответа.

Типичные ошибки

  • Если написать русский текст без UTF-8, в некоторых случаях могут появиться неправильные символы.
  • Если забыть закрыть тег, браузер часто сам исправит страницу, но лучше писать аккуратно.
🔗 Связь между JSON и HTML в реальном проекте
В курсе вы работали и с JSON-ответами (для API /docs, для тестирования), и с HTML-страницами. JSON отлично подходит для обмена данными между программами, а HTML — для показа страниц пользователю. Современные веб-приложения часто комбинируют оба подхода.
💡 Практический совет
При отладке смотрите, что именно возвращает сервер: если в браузере отображаются теги <html> — значит сервер вернул HTML. Если вы видите {"first_name": "Вася"} — значит сервер вернул JSON. FastAPI позволяет легко переключаться между этими форматами.

ТЕМА 6. Подключение HTML-шаблонов Jinja2Templates

Шаблон нужен, чтобы не писать HTML прямо внутри Python-функции. В Python остается логика, а в HTML-файле остается структура страницы. Jinja2 связывает эти две части.

В этой теме рассматривается отдавать не готовую строку, а HTML-файл из папки шаблонов.

Пример кода

from fastapi import FastAPI, Request
    from fastapi.templating import Jinja2Templates
    
    app = FastAPI()
    
    html = Jinja2Templates(directory="html")
    
    
    @app.get("/")
    def index(request: Request):
        return html.TemplateResponse(request, "index.html")

Разбор кода

  • from fastapi import FastAPI, Request импортирует FastAPI и Request. Request нужен шаблону, чтобы знать информацию о текущем HTTP-запросе.
  • from fastapi.templating import Jinja2Templates импортирует механизм шаблонов.
  • html = Jinja2Templates(directory="html") говорит приложению: HTML-файлы лежат в папке html.
  • Функция index принимает request: Request. Это объект с информацией о запросе браузера.
  • html.TemplateResponse(request, "index.html") возвращает не строку, а HTML-страницу из файла index.html.
  • Путь к файлу считается от папки directory="html". Значит, index.html должен лежать в папке html рядом с app.py.
  • Такой способ нужен, чтобы отделить Python-логику от HTML-разметки. Python выбирает данные, HTML отвечает за внешний вид.

Дополнительный пример

ТЕМА 7. Переменные, списки и bool в шаблоне Jinja2

В этой теме передаешь данные из Python в HTML и выводишь их внутри страницы.

Пример кода

from fastapi import FastAPI, Request
    from fastapi.templating import Jinja2Templates
    
    app = FastAPI()
    
    html = Jinja2Templates(directory="html")
    
    
    @app.get("/")
    def index(request: Request):
        return html.TemplateResponse(request, "index.html", {
            "title": "Страница",
            "header": "Васе Пупкину",
            "cats": 3,
            "cat_names": ["Барсик", "Мурзик", "Кузя"],
            "want_cat": True
        })

index.html


    <!DOCTYPE html>
    <html lang="en">
    <head>
        <meta charset="UTF-8">
        <title>{{ title }}</title>
    </head>
    <body>
        <h1>Эта страница принадлежит {{ header }}</h1>
        <p>У него {{ cats }} кота</p>
        Вот их имена:
        <ul>
            {% for cat in cat_names %}
                <li>{{ cat }}</li>
            {% endfor %}
        </ul>
        {% if want_cat %}
            <p>Вася хочет ещё одного кота</p>
        {%  endif %}
    </body>
    </html>

Разбор кода

  • В app.py функция index возвращает TemplateResponse и передает третий аргумент - словарь с данными.
  • Ключи словаря становятся переменными в HTML: title, header, cats, cat_names, want_cat.
  • В шаблоне {{ title }} означает: вставить значение переменной title в HTML.
  • {{ header }} вставляет строку "Васе Пупкину" в заголовок.
  • {{ cats }} вставляет число 3. Jinja2 сам превращает число в текст для HTML.
  • cat_names - список строк. В шаблоне {% for cat in cat_names %} перебирает список, как обычный цикл for в Python.
  • На каждой итерации переменная cat получает одно имя кота. Поэтому создается несколько <li>.
  • want_cat - bool. В шаблоне {% if want_cat %} показывает абзац только если значение True.
  • Важно: Jinja2 выполняется на сервере до отправки ответа. Браузер получает уже готовый HTML без команд {% for %} и {{ }}.

ТЕМА 8. Условия if/elif/else и список словарей в Jinja2

В этой теме страница начинает вести себя динамически: HTML меняется в зависимости от данных.

Пример кода

app.py

from fastapi import FastAPI, Request
        from fastapi.templating import Jinja2Templates
        
        app = FastAPI()
        
        html = Jinja2Templates(directory="html")
        
        
        @app.get("/")
        def index(request: Request):
            students = [
                {
                    "name": "Вася Пупкин",
                    "age": 18
                },
                {
                    "name": "Иван Иванов",
                    "age": 19
                },
                {
                    "name": "Петя Сидоров",
                    "age": 21
                }
            ]
            return html.TemplateResponse(request, "index.html", {
                "title": "Название",
                "header": "Заголовок",
                "mark": 4,
                "students": students
            })

index.html


        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <title>{{ title }}</title>
        </head>
        <body>
        <h1>{{ header }}</h1>
        
        {% if mark == 5 %}
            <p>Круто! Пятёрка!</p>
        {% elif mark == 4 %}
            <p>Четыре тоже хорошая оценка</p>
        {% else %}
            <p>Ну, в следующий раз повезёт</p>
        {% endif %}
        
        <ul>
            {% for student in students %}
                <li>
                    <p>Имя: {{ student["name"] }}</p>
                    <p>Возраст: {{ student["age"] }}</p>
                </li>
            {% endfor %}
        </ul>
        
        </body>
        </html>

Разбор кода

  • В app.py создается список students. Каждый элемент списка - словарь с ключами name и age.
  • В шаблон передается mark = 4. Шаблон проверяет оценку через if, elif, else.
  • {% if mark == 5 %} показывает текст для пятерки. {% elif mark == 4 %} показывает текст для четверки.
  • Если mark не 5 и не 4, сработает else. Это запасной вариант.
  • Цикл {% for student in students %} перебирает список словарей.
  • Внутри цикла student["name"] берет значение по ключу name, а student["age"] берет возраст.
  • Важная идея: Python готовит данные, Jinja2 решает, как эти данные показать.
  • Не стоит помещать сложную бизнес-логику в шаблон. Шаблон должен отвечать за отображение, а не за обработку базы или паролей.

ТЕМА 9. HTML-формы и получение данных через Form()

Форма является основным способом отправить данные со страницы на сервер. Поле формы имеет атрибут name. Именно это имя FastAPI использует, когда получает параметр через Form().

В этой теме рассматривается главный механизм сайтов: пользователь вводит данные, форма отправляет их на сервер, FastAPI принимает их через Form().

Пример кода

from typing import Annotated
        
        from fastapi import FastAPI, Form, Request
        from fastapi.templating import Jinja2Templates
        
        app = FastAPI()
        
        html = Jinja2Templates(directory="html")
        
        @app.get("/")
        def index(request: Request):
            return html.TemplateResponse(request, "form.html")
        
        
        @app.post("/form")
        def form(
            request: Request,
            title: Annotated[str, Form()],
            header: Annotated[str, Form()],
            cats: Annotated[int, Form()],
            want_cat: Annotated[str, Form()]
        ):
            return html.TemplateResponse(request, "index.html", {
                "title": title,
                "header": header,
                "cats": cats,
                "want_cat": want_cat == "yes"
            })

form.html


        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <title>Форма</title>
        </head>
        <body>
        <form action="/form" method="post">
                Имя: <input type="text" name="title"><br>
                Заголовок: <input type="text" name="header"><br>
                Число котов: <input type="number" name="cats"><br>
                Хочет ещё одного кота?: <input type="checkbox" name="want_cat" value="yes"><br>
                <button type="submit">Отправить</button>
              </form>
        </body>
        </html>

index.html


        <!DOCTYPE html>
        <html lang="en">
        <head>
            <meta charset="UTF-8">
            <title>{{ title }}</title>
        </head>
        <body>
            <h1>Эта страница принадлежит {{ header }}</h1>
            <p>У него {{ cats }} кота</p>
            Вот их имена:
            <ul>
                {% for cat in cat_names %}
                    <li>{{ cat }}</li>
                {% endfor %}
            </ul>
            {% if want_cat %}
                <p>Вася хочет ещё одного кота</p>
            {%  endif %}
        </body>
        </html>

Разбор кода

  • GET / возвращает form.html. Пользователь сначала получает страницу с формой.
  • <form action="/form" method="post"> означает: при нажатии кнопки отправить POST-запрос на /form.
  • Каждое поле input имеет атрибут name. Именно name становится именем поля в POST-запросе.
  • В Python функция form принимает title, header, cats, want_cat. Эти имена должны совпадать с name в HTML.
  • Annotated[str, Form()] означает: взять значение из формы. Без Form() FastAPI стал бы искать параметр в query.
  • cats: Annotated[int, Form()] показывает автоматическое преобразование: HTML отправляет текст, FastAPI преобразует его в int.
  • checkbox отправляет значение только если он отмечен. В коде want_cat сравнивается с "yes" и превращается в bool.
  • После обработки формы сервер возвращает index.html и передает туда данные, которые пришли из формы.
  • В учебном коде 9/html/index.html использует cat_names, но в POST /form cat_names не передается. Это хороший момент для разбора ошибки: если шаблон ждет переменную, Python должен ее передать.

  • feedback принимает данные формы. Это POST-запрос, потому что пользователь отправляет информацию на сервер.

2. Пользователь заполняет поля и нажимает "Отправить"
3. Браузер: POST /form с телом title=...&header=...&cats=3&want_cat=yes

5. Сервер возвращает index.html с подставленными данными
6. Браузер показывает результат
💡 Практический совет
Всегда проверяйте, что имена полей в HTML (атрибут name) точно совпадают с именами параметров в Python-функции. Для отладки временно верните return {"received": title} и посмотрите JSON-ответ — так вы увидите, что именно пришло на сервер.

ТЕМА 10. Список в памяти, таблица, checkbox, delete и RedirectResponse

В этой теме собираешь маленькое приложение: данные добавляются, показываются в таблице, удаляются, а сервер перенаправляет браузер обратно.

Пример кода

from typing import Annotated
        
        from fastapi import FastAPI, Request, Form
        from fastapi.templating import Jinja2Templates
        from fastapi.responses import RedirectResponse
        from pydantic import BaseModel
        
        app = FastAPI()
        html = Jinja2Templates(directory="html")
        
        kids = []
        
        
        class Kid(BaseModel):
            name: str
            age: int
            has_cat: bool
        
        
        @app.get("/")
        def table(request: Request):
            return html.TemplateResponse(request, "table.html", {
                "kids": kids
            })
        
        
        @app.get("/form")
        def form(request: Request):
            return html.TemplateResponse(request, "form.html")
        
        
        @app.post("/add")
        def add(
                name: Annotated[str, Form()],
                age: Annotated[int, Form()],
                has_cat: Annotated[str, Form()] = "no",
        ):
            kids.append(Kid(name=name, age=age, has_cat=has_cat=="yes"))
            return RedirectResponse("/", status_code=302)
        
        
        @app.get("/delete")
        def delete(index: int):
            kids.pop(index)
            return RedirectResponse("/")

ТЕМА 11. Cookies: память браузера

Cookie хранится на стороне браузера. Сервер устанавливает cookie в ответе, а затем браузер автоматически отправляет ее в следующих запросах на тот же сайт.

В этой теме рассматривается, как сервер может сохранить маленькую часть данных в браузере и получить ее при следующем запросе.

Пример кода

from typing import Annotated
        
        from fastapi import FastAPI, Cookie, Request, Form
        from fastapi.responses import RedirectResponse
        from fastapi.templating import Jinja2Templates
        
        
        app = FastAPI()
        html = Jinja2Templates(directory="html")
        
        
        @app.get("/")
        def index(
                request: Request,
                username: Annotated[str | None, Cookie()] = None,
                color: Annotated[str | None, Cookie()] = None
        ):
            return html.TemplateResponse(request, "index.html", {
                "username": username,
                "color": color
            })
        
        
        @app.post("/form")
        def form(username: Annotated[str, Form()], color: Annotated[str, Form()]):
            response = RedirectResponse("/", status_code=302)
            response.set_cookie(key="username", value=username)
            response.set_cookie(key="color", value=color)
            return response

ТЕМА 13. Сессии, uuid4 и хеширование sha256

Сессия решает важную задачу безопасности: браузеру не нужно хранить все данные пользователя. Достаточно хранить случайный идентификатор, по которому сервер найдет данные в своем хранилище.

В этой теме выполняется переход от простых cookie к более безопасной идее: браузер хранит session_id, а данные лежат на сервере.

Пример кода (часть 1 — базовая сессия)

from typing import Annotated
            from uuid import uuid4
            
            from fastapi import FastAPI, Form, Request, Cookie
            from fastapi.responses import RedirectResponse
            from fastapi.templating import Jinja2Templates
            
            
            users = {
                "ivan": "12345",
                "alex": "54321",
                "dima": "qwerty",
                "pavel": "password"
            }
            
            sessions = {}
            
            
            app = FastAPI()
            html = Jinja2Templates(directory="html")
            
            
            @app.get("/login")
            def login_form(request: Request):
                return html.TemplateResponse(request, "login.html")
            
            
            @app.post("/form")
            def form(login: Annotated[str, Form()], password: Annotated[str, Form()]):
                if login in users and users[login] == password:
                    session_id = str(uuid4())
                    sessions[session_id] = login
                    response = RedirectResponse("/", status_code=302)
                    response.set_cookie(key="session_id", value=session_id)
                    return response
                else:
                    return "Неверный логин или пароль"
            
            
            @app.get("/")
            def index(request: Request, session_id: Annotated[str, Cookie()] = None):
                if not session_id:
                    return RedirectResponse("/login")
                if session_id not in sessions:
                    return "Сессии не существует"
                return html.TemplateResponse(request, "index.html", {"login": sessions[session_id]})

Пример кода (часть 2 — с хешированием паролей)

from hashlib import sha256
            from typing import Annotated
            from uuid import uuid4
            
            from fastapi import FastAPI, Form, Request, Cookie
            from fastapi.responses import RedirectResponse
            from fastapi.templating import Jinja2Templates
            
            app = FastAPI()
            html = Jinja2Templates(directory="html")
            
            users = {}
            sessions = {}
            
            
            @app.get("/")
            def index(
                    request: Request,
                    session_id: Annotated[str, Cookie()] = None
            ):
                login = None
                if session_id and session_id in sessions:
                    login = sessions[session_id]
                response = html.TemplateResponse(request, "index.html", {
                    "login": login
            })
                if session_id not in sessions:
                    response.delete_cookie("session_id")
                return response
            
            
            @app.get("/login_form")
            def login_form(request: Request):
                return html.TemplateResponse(request, "login.html")
            
            
            @app.get("/reg_form")
            def reg_form(request: Request):
                return html.TemplateResponse(request, "reg.html")
            
            
            @app.post("/reg")
            def reg(
                    login: Annotated[str, Form()],
                    password: Annotated[str, Form()],
                    password2: Annotated[str, Form()]
            ):
                if password != password2:
                    return "Пароли не совпадают"
                password = sha256(password.encode("utf-8")).hexdigest()
                users[login] = password
                return RedirectResponse("/", status_code=302)
            
            
            @app.post("/login")
            def login(
                    login: Annotated[str, Form()],
                    password: Annotated[str, Form()]
            ):
                if login not in users:
                    return "Такого пользователя нет"
                password = sha256(password.encode("utf-8")).hexdigest()
                if users[login] != password:
                    return "Пароль неверный"
                session_id = str(uuid4())
                sessions[session_id] = login
                response = RedirectResponse("/", status_code=302)
                response.set_cookie("session_id", session_id)
                return response

Разбор кода

  • Тема 13 улучшает вход. Теперь в cookie хранится не login, а случайный session_id.
  • users = {} хранит пользователей, sessions = {} хранит активные сессии.
  • sha256(password.encode("utf-8")).hexdigest() превращает пароль в хеш. Хеш - строка фиксированного вида, полученная из пароля.
  • При регистрации в users сохраняется не сам пароль, а его хеш.
  • При входе введенный пароль снова хешируется. Потом сравниваются два хеша.
  • uuid4() создает случайный идентификатор сессии. str(uuid4()) превращает его в строку для cookie.
  • sessions[session_id] = login сохраняет на сервере связь: этот session_id принадлежит этому login.
  • Браузер получает только session_id. На главной странице сервер проверяет, есть ли такой session_id в словаре sessions.
  • Если session_id не найден, response.delete_cookie("session_id") удаляет неправильную cookie из браузера.
  • Важно: sha256 без соли в учебном проекте показывает идею хеширования, но для реальных паролей используют специализированные библиотеки. В рамках курса достаточно понять принцип: пароль не нужно хранить как обычный текст.

Дополнительный пример (с выходом из системы)

from hashlib import sha256
            from uuid import uuid4
            
            users = {}
            sessions = {}
            
            @app.post("/reg")
            def reg(login: Annotated[str, Form()], password: Annotated[str, Form()]):
                password_hash = sha256(password.encode("utf-8")).hexdigest()
                users[login] = password_hash
                return RedirectResponse("/login_form", status_code=302)
            
            @app.post("/login")
            def login(login: Annotated[str, Form()], password: Annotated[str, Form()]):
                password_hash = sha256(password.encode("utf-8")).hexdigest()
                if login not in users or users[login] != password_hash:
                    return "Неверный логин или пароль"
                session_id = str(uuid4())
                sessions[session_id] = login
                response = RedirectResponse("/", status_code=302)
                response.set_cookie("session_id", session_id)
                return response
            
            @app.get("/logout")
            def logout(session_id: Annotated[str, Cookie()] = None):
                if session_id in sessions:
                    sessions.pop(session_id)
                response = RedirectResponse("/", status_code=302)
                response.delete_cookie("session_id")
                return response

Разбор дополнительного примера

  • В регистрации пароль сразу превращается в password_hash. Открытый password не сохраняется.
  • Во входе введенный пароль снова превращается в hash. Если hash совпал с сохраненным, пароль правильный.
  • session_id создается только после успешного входа. Значит, чужой пользователь не получит сессию.
  • sessions хранит session_id на сервере. Это безопаснее, чем хранить login в cookie.
  • logout удаляет сессию с сервера и cookie из браузера. Нужно делать оба действия: иначе одна часть останется.
  • Такой код готовит к базе данных: в занятиях 17-18 session_id будет храниться не в словаре, а в таблице sessions.

Типичные ошибки

  • Если session_id есть в cookie, но нет в sessions, пользователь не должен считаться вошедшим.
  • Нельзя сравнивать открытый password с хешем в users. Нужно сначала хешировать введенный пароль.

В проектных занятиях: база данных SQLite + SQLAlchemy вместо словарей users и sessions.
⚠️ Важное замечание про безопасность
В реальном проекте не используйте sha256 без соли для паролей! Применяйте специализированные библиотеки: passlib или bcrypt. В учебном коде sha256 используется только для демонстрации принципа хеширования.

При отладке сессий добавьте временный маршрут /show_sessions, который возвращает словарь sessions в JSON. Это поможет понять, какие сессии активны на сервере и какие session_id хранятся в браузере.

ТЕМА 14. SQLAlchemy-модели: Python-классы как таблицы

SQLAlchemy позволяет описывать таблицы базы данных с помощью Python-классов. Класс соответствует таблице, объект класса соответствует строке таблицы, а атрибуты соответствуют столбцам.

В этой теме рассматривается описывать таблицу базы данных через Python-класс.

Пример кода

from datetime import datetime
from sqlalchemy.orm import (
    mapped_column,
    Mapped,
    DeclarativeBase
)


class Base(DeclarativeBase):
    pass


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str]
    age: Mapped[int]
    login: Mapped[str]
    email: Mapped[str]
    phone: Mapped[str]

class Book(Base):
    __tablename__ = "books"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    author: Mapped[str]
    year: Mapped[int]
    genre: Mapped[str]

class Post(Base):
    __tablename__ = "posts"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    content: Mapped[str]
    posted_at: Mapped[datetime] = mapped_column(default=datetime.now)
    author_id: Mapped[int]

Разбор кода

  • DeclarativeBase - базовый класс SQLAlchemy. Все модели наследуются от Base.
  • class Base(DeclarativeBase): pass создает основу, через которую SQLAlchemy узнает обо всех таблицах.
  • User, Book, Post - модели. Модель - Python-класс, который соответствует таблице в базе данных.
  • __tablename__ задает имя таблицы. Например, User хранится в таблице users.
  • id: Mapped[int] = mapped_column(primary_key=True) создает столбец id и делает его главным ключом.
  • Главный ключ нужен, чтобы однозначно находить запись. Например, пользователь с id=3 или книга с id=8.
  • Mapped[str], Mapped[int], Mapped[datetime] показывают типы данных в столбцах.
  • posted_at: Mapped[datetime] = mapped_column(default=datetime.now) означает: при создании записи дата поставится автоматически.
  • author_id: Mapped[int] в Post показывает связь по id: пост принадлежит какому-то пользователю.
  • В коде 17-18 похожая идея используется для книг: поле added_by хранит id пользователя, который добавил книгу.

Дополнительный пример

from datetime import datetime
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass

class Task(Base):
    __tablename__ = "tasks"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    is_done: Mapped[bool] = mapped_column(default=False)
    created_at: Mapped[datetime] = mapped_column(default=datetime.now)
    user_id: Mapped[int]

class Comment(Base):
    __tablename__ = "comments"

    id: Mapped[int] = mapped_column(primary_key=True)
    text: Mapped[str]
    task_id: Mapped[int]
    author_id: Mapped[int]

Разбор дополнительного примера

  • Task - новая таблица задач. У каждой задачи есть id, title, is_done, created_at и user_id.
  • is_done имеет default=False. Если при создании задачи не указать is_done, база поставит False.
  • created_at имеет default=datetime.now. Это похоже на posted_at из модели Post в коде курса.
  • user_id хранит id пользователя. Это простой способ связать задачу с автором.
  • Comment показывает вторую связанную таблицу: комментарий относится к задаче через task_id и к автору через author_id.
  • Даже без relationship можно понять связь по числам id. В учебном курсе этого достаточно для подготовки к 17-18.

Типичные ошибки

  • Если забыть primary_key=True, у таблицы не будет нормального главного ключа.
  • Если забыть Base.metadata.create_all(engine), таблицы не создадутся в SQLite.

ТЕМА 15. SQLite, engine, Session, select и сохранение данных

SQLite является файловой базой данных. Это удобно для обучения: отдельный сервер базы данных не требуется, данные сохраняются в локальном файле.

В этой теме данные перестают исчезать после перезапуска сервера, потому что сохраняются в SQLite.

Пример кода

from typing import Annotated

from fastapi import FastAPI, Form, Request
from fastapi.templating import Jinja2Templates
from fastapi.responses import RedirectResponse
from sqlalchemy import create_engine, select
from sqlalchemy.orm import Session

from models import User, Base

app = FastAPI()
html = Jinja2Templates(directory="html")

engine = create_engine("sqlite:///database.db")
Base.metadata.create_all(engine)


@app.get("/")
def index(request: Request):
    with Session(engine) as session:
        data = session.scalars(select(User)).all()
        return html.TemplateResponse(request, "index.html", {"data": data})


@app.post("/add")
def add(
        name: Annotated[str, Form()],
        age: Annotated[int, Form()],
        login: Annotated[str, Form()],
        email: Annotated[str, Form()],
        phone: Annotated[str, Form()]
):
    with Session(engine) as session:
        session.add(User(
            name=name,
            age=age,
            login=login,
            email=email,
            phone=phone
        ))
        session.commit()
    return RedirectResponse("/", status_code=302)


@app.get("/delete")
def delete(
        id: int
):
    with Session(engine) as session:
        user = session.get(User, id)
        session.delete(user)
        session.commit()
    return RedirectResponse("/", status_code=302)

Разбор кода

  • create_engine("sqlite:///database.db") подключает SQLite-базу в файле database.db.
  • SQLite удобна для обучения, потому что база хранится в одном файле и не требует отдельного сервера базы данных.
  • Base.metadata.create_all(engine) создает таблицы по моделям, если их еще нет.
  • with Session(engine) as session открывает рабочую сессию с базой. Через session выполняются запросы.
  • session.scalars(select(User)).all() получает все записи User из таблицы users.
  • В GET / эти записи передаются в index.html как data. Шаблон может вывести таблицу пользователей.
  • POST /add принимает данные формы и создает User(...). Затем session.add(...) добавляет объект в сессию.
  • session.commit() сохраняет изменения в базе. Без commit запись не будет окончательно сохранена.
  • GET /delete получает id, делает session.get(User, id), потом session.delete(user) и session.commit().
  • База данных решает проблему списков в памяти: после перезапуска сервера пользователи останутся в database.db.

Разбор дополнительного примера

  • Пример повторяет CRUD из темы 16, но для модели Task.
  • GET / получает все задачи из базы через select(Task).all(). Это аналог вывода списка kids, но данные теперь берутся из SQLite.
  • POST /add создает новую задачу и сохраняет ее через session.add и session.commit.
  • GET /delete удаляет задачу по id. В этой теме есть проверка if task, чтобы не удалять None.
  • RedirectResponse после add и delete возвращает пользователя на главную страницу с обновленным списком.
  • Этот пример показывает переход от временного списка к постоянному хранению данных.

Типичные ошибки

  • Забытый commit - самая частая ошибка при добавлении и удалении.
  • session.get(User, id) может вернуть None, если записи с таким id нет.

Итоговый путь одного запроса

Теперь соберем всю логику в одну цепочку. Так должен рассуждать разработчик, когда страница не открывается или данные не появляются.

  1. Пользователь открывает страницу / в браузере.
  2. Браузер отправляет HTTP GET / на сервер FastAPI.
  3. FastAPI находит декоратор @app.get("/") и вызывает функцию index.
  4. index читает cookie, если они нужны.
  5. index открывает Session(engine), если нужно прочитать базу данных.
  6. Python-код получает данные: список пользователей, книг, задач или заметок.
  7. TemplateResponse передает данные в HTML-шаблон.
  8. Jinja2 выполняет {{ переменные }}, {% if %}, {% for %}.
  9. Сервер отправляет готовый HTML браузеру.
  10. Браузер показывает страницу пользователю.

Итоговый путь отправки формы

Форма - это не просто HTML. Это способ заставить браузер собрать данные и отправить их в нужный POST-маршрут FastAPI.

  1. Пользователь открывает HTML-форму.
  2. Вводит данные в input, select, textarea или checkbox.
  3. Нажимает button type="submit".
  4. Браузер отправляет POST-запрос на action формы.
  5. FastAPI вызывает функцию с @app.post(...).
  6. Form() берет значения из полей по их name.
  7. Python проверяет данные, создает объект или хеширует пароль.
  8. Данные сохраняются в список, словарь, cookie, session или базу.
  9. Сервер возвращает RedirectResponse.
  10. Браузер открывает новую страницу и показывает обновленный результат.
